# Tickets — automation-template-export

由 §0–§9 規格經 **Tickets branch** 切出的 tracer bullet。每張票切穿 schema / API / UI / tests
的一條窄但完整的路徑，做完可以獨立 demo，塞得進一個全新的 context window。

## 依賴圖

```
01 匯出模板成 JSON
   └─▶ 02 匯入 JSON 存成 Draft
          ├─▶ 03 Schema 驗證與錯誤呈現
          │      ├─▶ 04 匯入預覽頁
          │      └─▶ 06 AI 生成走同一條匯入路徑
          ├─▶ 05 同名衝突處理
          └─▶ 07 系統啟動載入 Seed 模板
```

**Frontier（blocker 都完成、現在就能抓的票）**：一開始只有 `01`。
`02` 落地後 frontier 變成 `03` / `05` / `07` 三張 —— 互不阻塞，可以同時發包給三個 agent。

## 票

| # | 標題 | Blocked by | 對應 FR |
|---|---|---|---|
| 01 | 匯出模板成 JSON 檔 | — | FR-1 |
| 02 | 匯入 JSON 檔並存成 Draft | 01 | FR-2, FR-6 |
| 03 | Schema 驗證與錯誤呈現 | 02 | FR-3, FR-9 |
| 04 | 匯入預覽頁 | 03 | FR-4 |
| 05 | 同名衝突處理 | 02 | FR-5 |
| 06 | AI 生成內容走同一條匯入路徑 | 03 | FR-7 |
| 07 | 系統啟動載入 Seed 模板 | 02 | FR-8 |

## 為什麼 01 擋著 02

匯出先做，JSON 的格式契約就跟著落地了 —— 02 匯入才有明確的東西可以吃。
反過來先做匯入，格式只能用猜的，等匯出做完往往要回頭改。

這是**垂直切**跟**按層切**的差別：按層切會是「先做完所有 schema → 再做完所有 API → 最後畫面」，
那樣在最後一步之前什麼都測不了。
